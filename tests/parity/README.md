## 1. Rebuild the C++ baseline (about 1 min with -j12)

```powershell
mingw32-make -f tests/parity/Makefile -j12          # -> build\cpp\cpp_driver.exe (objects in build\cpp\obj)
mingw32-make -f tests/parity/Makefile clean         # remove the objects
```

What is built (nothing is written inside `upstream\`):
- `build\cpp\include\config.h` is hand written: `THORVG_CPU_ENGINE_SUPPORT`, `THORVG_SVG_LOADER_SUPPORT`,
  `THORVG_PNG_LOADER_SUPPORT`, `THORVG_GIF_LOADER_SUPPORT`, `THORVG_JPG_LOADER_SUPPORT`, `THORVG_SFNT_LOADER_SUPPORT`, `THORVG_TTF_LOADER_SUPPORT`,
  `THORVG_WEBP_LOADER_SUPPORT`, `THORVG_FILE_IO_SUPPORT` (GIF: `modules/gif/load/tvgGif*.cpp`, `-I modules/gif/load`; WebP: `modules/webp/static/{tvgWebpLoader.cpp,dec,dsp,utils}/*.cpp`, `-I modules/webp/static`, added with unit L5c-C).
  NOT defined: `THORVG_THREAD_SUPPORT` (single thread, synchronous), `THORVG_AVX_SUPPORT` (scalar raster only),
  `THORVG_PARTIAL_RENDER_SUPPORT`, Lottie/GL/WebGPU/OTF/OpenMP/log.
  JPG: `modules/jpg/static/tvgJpgd.cpp` + `tvgJpgLoader.cpp`, `-I modules/jpg/static` (see `tests\parity\Makefile`).
- Sources = the lists of `src\meson.build` files: common/*.cpp, renderer/*.cpp, renderer/cpu_engine/*.cpp
  (incl. `tvgSwRasterSimd.cpp`, which is empty without AVX), modules/raw, modules/svg, modules/sfnt (ttf),
  modules/png/static (lodepng).
- Flags: `g++ -std=c++14 -O2 -DNDEBUG -ffp-contract=off -fno-math-errno -DTVG_STATIC -DNOMINMAX -w`
  (no `-ffast-math`, no FMA: the float math is plain IEEE binary32 with SSE2, like the Nim `float32` code).
- Nothing was dropped: every requested module built (CPU engine, SVG, PNG, raw, TTF).

## 2. The driver `cpp_driver.exe`

```
cpp_driver <scene> <w> <h> [--dump <prefix>] [--repeat N]
scene = shapes | shapes:<part> | svg:<file.svg> | png:<file.png> | jpg:<file.jpg> | webp:<file.webp> | pngrot:<file.png>[@deg,scale,shear,opacity] | gif:<file.gif>[:f1,f2,..] | text | text:<file.ttf>
```
- Canvas = `SwCanvas`, `ColorSpace::ARGB8888` (premultiplied), buffer zero-filled (transparent), `stride = w`.
- `--dump p` writes `p.argb` (w*h little-endian uint32, premultiplied ARGB, no header) and `p.ppm` (P6, composited over white).
- stdout, one line: `scene=<s> size=<w>x<h> fnv1a64=<hex> nonzero=<n> opaque=<n>` (FNV-1a 64 over the .argb bytes).
- `shapes:<part>`, part = `rect roundrect ellipse star_nonzero star_evenodd lingrad radgrad spread_reflect spread_repeat
  gradstroke caps joins dash transform opacity clip mask blend nested` (design canvas 400x300; `shapes` = all parts in
  that order). See the source for exact coordinates: the Nim driver must build the identical scene.
- `svg:` / `png:`: `Picture::load(file)`, native size `(w,h)`, `scale = min(W/w, H/h)`, `size(w*scale, h*scale)`,
  `translate((W-nw)/2, (H-nh)/2)` (float32 arithmetic). When W,H equal the native size the picture is drawn 1:1.
- `jpg:<file.jpg>`: same fitting as `svg:`/`png:` (`fitPicture`). A file the C++ loader rejects prints `cannot load` on stderr and exits 2 (the rc is part of the comparison); a decode failure after a valid header leaves an empty canvas (`nonzero=0`). 99 cases `jpg_*` (96 files, see section 5).
- `pngrot:<file>[@deg,scale,shear,opacity]` (defaults `30,1,0,255`): a PNG drawn through a rotated/sheared/scaled matrix, i.e. the texture-mapper path (L3). The matrix `M = T(c)*R(deg)*Shear(x += k*y)*S(scale)*T(-size/2)` (`c` = canvas centre, `size` = native size) is computed in float64, rounded to float32 once, and applied with `Picture::transform(Matrix)` + `opacity`. Identical in `cpp_driver.cpp` (`rotPicture`) and `tests\parity\rotscene.nim`.
- `gif:<file>[:f1,f2,..]` (frame list default `0`): `Animation::gen()`, `picture()->load(file)`, then `Animation::frame(f)` for each list entry in order (results ignored, so `3,1` exercises the backward/rebuild path; non-numeric entries count as 0, `99` and `-1` are out-of-range probes), then the picture is fitted like `svg:`/`png:`. The GIF test files are produced by `node tests\parity\mkgif.js tests\data\gif`. Identical in `cpp_driver.cpp` (`gifPicture`) and `nim_driver.nim`. 172 cases `gif_*` (all 16 files, every frame, sequences, scaled, out-of-range, fractional).
- `text`: `Text::load("C:\Windows\Fonts\arial.ttf")`, `font(nullptr)` (any loaded font), 4 text lines (sizes 40/14/24/30, one
  rotated -20 deg) + an italic 48 pt linear-gradient text. `text:<ttf>` uses another font (`PublicSans-Regular.ttf`).
- Exit code 0 ok, 2 usage/load/render error (message on stderr).

- `tests\data\jpg\*.jpg` + `index.txt` (`name w h ok|bad`): 96 JPEGs from `node tests\parity\mkjpg.js tests\data\jpg` (own encoder: gray, 4:4:4, 4:2:0, 4:2:2, 4:4:0, baseline/SOF1/progressive incl. spectral-only and per-component scans, restart intervals 1..9, optimized Huffman tables, 16-bit DQT, APP/COM markers, noise at q10..q100, plus truncated/corrupt/unsupported variants). If you change the generator, delete `migration\golden\jpg_*` and re-capture them from the C++ driver (about 4 min, 2.5 s per case); check `nonzero=` of the new `.out` files so no case is vacuously empty.
- `tests\data\upstream\`: copies of `upstream\thorvg\test\res` files `test0..5.svg`, `test.png` (511x511 RGBA), `test2.png` (3x2, 1-bit palette), `PublicSans-Regular.ttf`.

## Known quirks of the original (golden = what the original does)
- `style_use.svg`: CSS `#c { fill: hsl(...) }` renders black; `<use>` with `transform=rotate` partly leaves the viewbox.
- `test1.svg` uses SVG filters (feGaussianBlur...) that the CPU SVG loader ignores.
- `rgb8_trns.png` / gray tRNS: the colour key does not match any pixel, so it equals the plain `rgb8` result.
- Not covered (out of MVP scope): scene effects, partial rendering, OTF, Lottie (GIF is covered by `gif_*`, JPG by `jpg_*`, WebP by `webp_*`), threads, AVX2 path. (Rotated images are covered by the `pngrot_*` cases, bit-exact.)
  Note `-O2` vs the AVX2 path: the AVX2 rasterizer is not compiled in, so golden = scalar code paths.

## 6. WebP (`webp_*`, unit L5c-C)

- `webp:<file.webp>` = `fitPicture` like `png:`/`jpg:` (open failure: `cannot load`, rc 2, part of the comparison; decode failure after a valid open: empty canvas, `nonzero=0`).
- 368 cases from `tests\parity\gen_webp_cases.ps1`: every file of `tests\data\webp` (17 real, 168 `gen/` VP8L, 29 `lossy/`, 143 `alph/`) at native size when small (direct blit of the decoded premultiplied bitmap), else scaled to fit (a fraction of the native size), plus 11 resampled / native / enlarged variants. The header size is read by the script; unreadable files use 33x17.
- `alph/` is produced by `nim c -r tests/parity/mkwebp_alph.nim tests/data/webp/alph`: ALPH chunks (raw and lossless; filters none/horizontal/vertical/gradient; pre-processing flag; palette/predictor/meta-prefix lossless streams), VP8X flag combinations, unknown chunks, bad RIFF/chunk sizes, truncations, raw bitstreams without RIFF, VP8L in VP8X, invalid ALPH headers, tiny files. `cases()` in that file also carries the expected alpha plane and is used by `tests\test_webp.nim`.
- 27 cases exit with rc 2 (`cannot load`), 21 more decode to an empty canvas (including the all-zero-alpha plane); the other 320 have `nonzero > 0`.
- Golden captured ONLY from the C++ driver (`run_cases.ps1 -Exe build\cpp\cpp_driver.exe -OutDir migration\golden -Filter webp_`), second C++ run identical. Nim result: 368/368 bit-exact on the release and debug drivers, whole suite 728/728 (release). The older 360 golden files were not touched and the rebuilt C++ driver still reproduces them.
## 7. GL parity (`tests\gl\`, unit G5)

The Nim GL engine (`engine/gl`, facade `thorvg/engine/gl/glcanvas`) is compared with the ORIGINAL C++ GL engine (`THORVG_GL_TARGET_GL`, WGL, OpenGL 3.3 core) on the same machine and GPU. Golden = `migration\golden_gl` (728 cases of `cases.txt` + 56 `glx_*` cases of `cases_glx.txt`), captured ONLY from the C++ GL driver. Bit-exact is only meaningful on the same GPU driver (captured on AMD Radeon, driver 23.19.24.251211).

```powershell
. "C:\Users\C08937\.config\opencode\skills\nim-toolchain-win\scripts\env.ps1"
# 1. original C++ GL driver (build\cppgl\cpp_gl_driver.exe)
mingw32-make -f tests/gl/Makefile.gl -j8
# 2. Nim GL driver (always pass -Out and -nimcache for files under tests\gl)
nimc.ps1 -Src tests\gl\nim_gl_driver.nim -Mode release -Strict -Out build\nim_gl_driver_release.exe -Extra '--nimcache:build\nimcache\glrel'
nimc.ps1 -Src tests\gl\nim_gl_driver.nim -Mode debug   -Strict -Out build\nim_gl_driver_debug.exe   -Extra '--nimcache:build\nimcache\gldbg'
# 3. (re)capture golden - C++ only (~1.4 s per case)
tests\parity\run_cases.ps1 -Exe build\cppgl\cpp_gl_driver.exe -OutDir migration\golden_gl
tests\parity\run_cases.ps1 -Exe build\cppgl\cpp_gl_driver.exe -OutDir migration\golden_gl -Cases migration\cases_glx.txt
# 4. parity (tolerance 0, per-group table, failures in <OutDir>\_failures.txt)
tests\gl\run_gl_cases.ps1 -Mode release [-Cases migration\cases_glx.txt] [-Filter webp_] [-Tol 0]
tests\gl\run_gl_cases.ps1 -Mode debug
# informational: GL vs CPU golden deltas per group -> migration\GL_SANITY.md
tests\gl\gl_sanity.ps1
```

- Run only ONE GPU job at a time. The scenes are the same as for the CPU (`driver_common.nim`); `glx:<name>` scenes (blend, scene blend, mask, effects, gradients, thin, trim, clip, nested opacity) exist only for GL (`tests\gl\glx_scene.nim` <-> `buildGlx` in `cpp_gl_driver.cpp`, keep both in lock-step).
- Dumps: `.argb` (premultiplied ARGB, top row first), `.rgba` (raw glReadPixels, bottom row first), `.ppm`.
- Results: 728/728 and glx 56/56 bit-exact, tolerance 0, release and debug.
- Known transient: `jpg_sep_420_53x37` produced a different image in 1 of ~900 runs of the C++ driver (36 px, max delta 120); the golden is the majority hash. Re-run before treating a lone failure as real (D-G5-4).
